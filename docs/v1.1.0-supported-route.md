# LazyBuddy v1.1.0: supported route

`release/v1.1.0` is the current source branch. It is not a GitHub Release or a
marketplace publication.

1. Clone the source branch and use its durable lifecycle entrypoint:

   ```bash
   git clone --branch release/v1.1.0 https://github.com/elvinzhao10/LazyBuddy.git
   node "<checkout>/lazybuddy-plugin/scripts/lazybuddy-lifecycle.js" onboard \
     --source https://github.com/elvinzhao10/LazyBuddy/tree/release/v1.1.0 \
     --install-root "<absolute-install-root>" --project "<absolute-project-root>" --json
   ```

2. Use the installed launcher for package checks:

   ```bash
   node "<install-root>/LazyBuddy/launcher.js" status \
     --install-root "<install-root>" --project "<project-root>" --json
   ```

3. Choose one host route. For CodeBuddy CLI and CodeBuddy IDE with the CLI
   available, add the launcher-reported release root as a local marketplace and
   install `lazybuddy@lazybuddy`. For WorkBuddy, choose the release-local
   `lazybuddy-plugin` directory containing `.workbuddy-plugin/plugin.json` in
   the current build's visible plugin/marketplace flow.

4. Start a fresh host session. Package checks prove package readiness only.
   Host readiness requires a visible LazyBuddy Skill or command and all six MCP
   servers: `run-ledger`, `verification`, `status-dashboard`, `context-graph`,
   `code-intel`, and `docs`.

The Skills/manual-MCP route is recovery-only and cannot coexist with the full
plugin route for the same project. Do not create a GitHub Release, publish a
marketplace artifact, or claim host readiness without fresh-session evidence.
