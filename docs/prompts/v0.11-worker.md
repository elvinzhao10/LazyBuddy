## Prompt to delegate

You are working in the LazyBuddy workspace at `/Users/Admin/Desktop/lazybuddy`. This is a WorkBuddy-native recreation of LazyCodex (the OmO agent harness for Codex). The whole project is a **version 0 build** — every phase is numbered `v0.N`. v0.1–v0.10 are complete and approved.

**Your task: execute phase v0.11 — dogfood LazyBuddy on itself.**

This is not a build phase — it's a **self-test**. You use the LazyBuddy system (the skills, agents, hooks, state scripts, MCP servers, and verification tools built in v0.2–v0.10) to perform a real end-to-end workflow on this workspace. The goal: prove the harness can plan, execute, verify, review, and close a real task — and honestly report what works and what doesn't.

### Choose a dogfood task

Pick ONE small but meaningful task from this list (or propose your own):
- Fix a parity-ledger inconsistency (e.g., a status that's marked "implemented" but isn't really)
- Add a missing verification detail to a skill
- Improve a smoke-check script
- Tighten an agent boundary that's too loose
- Fix a stale version/CHANGELOG metadata issue

The task must be: (a) real (not fabricated), (b) small enough to complete in one session, (c) meaningful (not trivial), (d) verifiable (you can run checks to prove it's done).

### Execute the full LazyBuddy workflow

Use the actual system components — don't simulate. Create real state, run real scripts, produce real evidence.

**Step 1: init-deep** — Read `workbuddy.md` and the project structure. Confirm you understand the workspace.

**Step 2: ulw-plan** — Create a plan for the chosen task.
- Run `bash lazybuddy-plugin/scripts/state/create-run.sh dogfood-v0.11 "<task objective>"` to create a run.
- Write a plan to `.lazybuddy/runs/dogfood-v0.11/plan.md` with `## TODOs` checkboxes.
- Update `state.json` with `status: "executing"` and `plan_reference`.

**Step 3: start-work** — Execute the plan.
- Use `bash lazybuddy-plugin/scripts/loop/next-task.sh dogfood-v0.11` to get the next task.
- Implement the task (make the actual changes to files).
- Use `bash lazybuddy-plugin/scripts/state/update-task.sh dogfood-v0.11 <task_id> done` to mark progress.
- Check off the plan checkbox (`- [ ]` → `- [x]`).

**Step 4: ulw-loop** (if needed) — If the task has multiple steps, loop back to step 3.

**Step 5: verifier** — Run verification.
- Run `bash lazybuddy-plugin/scripts/lazybuddy-verify.sh` — capture the output.
- Run `bash lazybuddy-plugin/scripts/lazybuddy-docs-check.sh` — capture.
- Run `bash lazybuddy-plugin/scripts/lazybuddy-security-check.sh` — capture.
- Record results in `.lazybuddy/runs/dogfood-v0.11/verification/`.

**Step 6: reviewer** — Review the changes.
- Review changed files against the plan intent.
- Check for overreach, missing docs, regressions.
- Produce an accept/reject/revise decision.
- Record in `.lazybuddy/runs/dogfood-v0.11/review/`.

**Step 7: librarian** — Update memory.
- Update `docs/lazybuddy-parity-ledger.md` if parity changed.
- Update `docs/lazybuddy-known-gaps.md` if new gaps discovered.
- Update `docs/lazybuddy-risk-register.md` if new risks found.
- Record in `.lazybuddy/runs/dogfood-v0.11/memory_updates/`.

**Step 8: finalize** — Run `bash lazybuddy-plugin/scripts/loop/finalize-run.sh dogfood-v0.11`.
- If it passes: write `final_report.md`.
- If it refuses: document what's blocking.
