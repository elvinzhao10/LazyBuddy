### What to produce

**1. State directory structure** — create `.lazybuddy/` with subdirs:
```
.lazybuddy/
  context/         # init-deep output (index.md, commands.json, project-map.json)
  runs/            # per-run directories
  templates/       # plan templates, run-log templates
  logs/            # aggregate logs
  cache/           # transient caches
```

**2. Per-run directory structure** — each run creates:
```
.lazybuddy/runs/<run_id>/
  state.json           # the state schema (see below)
  events.jsonl         # append-only event log (one JSON per line)
  plan.md              # the plan being executed (with ## TODOs checkboxes)
  checkpoints/         # periodic state snapshots
  agent_outputs/       # saved subagent responses
  artifacts/           # produced files
  evidence/            # verification proof artifacts (SubagentStop hook checks here)
  verification/        # gate results
  review/              # review decisions
  memory_updates/      # librarian update records
  final_report.md      # completion report
```

**3. State schema** (`state.json`) — use the schema from the spec (plan/v0.7 lines 33-72), BUT add two flat fields for hook compatibility:
- `status`: top-level string (`"created"|"planning"|"executing"|"blocked"|"verifying"|"reviewing"|"complete"|"failed"|"cancelled"`) — the Stop hook reads this
- `plan_reference`: top-level path to `plan.md` — the Stop hook reads this to parse checkboxes
- Map `status: "active"` → `"executing"` and `status: "paused"` → `"blocked"` for hook compatibility (or update the hook to accept the new status values — document your choice)

**4. State management scripts** (`lazybuddy-plugin/scripts/state/*.sh`, all executable):
| Script | Purpose |
| --- | --- |
| `create-run.sh` | Initialize a new run: create directory structure, write initial state.json, append `run_created` event |
| `load-run.sh` | Read and output state.json for a given run_id |
| `update-task.sh` | Update a task's status/changed_files/evidence in state.json; append event. Atomic write (tmp + rename) |
| `append-event.sh` | Append a JSON event to events.jsonl (never modify/delete existing lines) |
| `checkpoint.sh` | Snapshot state.json + plan.md to checkpoints/<timestamp>/; update `last_checkpoint` in state.json |
| `recover-run.sh` | Restore from latest checkpoint; replay events.jsonl since checkpoint to rebuild state |
| `summarize-run.sh` | Output a human-readable run summary (status, tasks done/remaining, evidence count, blockers) |
| `validate-state.sh` | Validate state.json against the schema (required fields, valid status values, task integrity) |
| `list-runs.sh` | List all runs with status and last-updated timestamp |
| `latest-run.sh` | Output the run_id of the most recently updated active run |

**5. Loop scripts** (`lazybuddy-plugin/scripts/loop/*.sh`, all executable):
| Script | Purpose |
| --- | --- |
| `next-task.sh` | Find the next queued task whose dependencies are met; mark it `running`; output task details for the orchestrator |
| `run-cycle.sh` | Execute one loop iteration: next-task → (delegate to implementer) → update-task → check verification → check review → checkpoint if needed. Returns `continue`/`blocked`/`complete` |
| `classify-failure.sh` | Classify a task failure (retry/fallback/blocker/human-needed); append classification to events.jsonl |
| `create-repair-task.sh` | Create an explicit repair task in state.json based on failure classification |
| `finalize-run.sh` | Check all verification gates passed + review accepted; if yes, set status `complete`, write final_report.md; if no, refuse and report what's missing |

### Critical rules (from the spec)

- **All state writes must be atomic** — write to tmp file, then rename (prevents corruption on crash).
- **Every state transition must append to events.jsonl** — the event log is the source of truth; state.json is a snapshot.
- **State must be recoverable** from latest checkpoint + events.jsonl replay.
- **Validate state against schema before saving** — `validate-state.sh` runs before every write.
- **Never mark run complete** unless verification gates passed AND review accepted. `finalize-run.sh` must refuse otherwise.
- **Do not rely on chat context for status** — all status lives in state.json + events.jsonl.
- **All agent outputs must be saved** before synthesis — no in-memory-only agent results.
- **Repair tasks must be explicit** — created via `create-repair-task.sh`, not hidden in prose.

### Hard constraints

- **All scripts use `${CODEBUDDY_PLUGIN_ROOT}`** for plugin-relative paths and `$CWD/.lazybuddy/` for run state.
- **All scripts are executable** (`chmod +x`).
- **Shell scripts** with `#!/usr/bin/env bash`; use `python3` for JSON manipulation.
- **Hook compatibility:** `state.json` must have top-level `status` and `plan_reference` fields that the v0.6 `stop-gate.sh` can read. Test this.
- **Evidence path compatibility:** the `evidence/` subdirectory must exist so `subagent-stop.sh` can verify `EVIDENCE_RECORDED:` paths.
- **No secrets in events.jsonl** — redact before appending.
- **Update `docs/lazybuddy-parity-ledger.md`** — mark the state ledger and loop as implemented.
