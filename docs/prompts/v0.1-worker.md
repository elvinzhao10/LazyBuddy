### Design principles (from the spec)

1. Preserve LazyCodex method semantics.
2. Use WorkBuddy-native features creatively.
3. Do not blindly copy files unless copying is explicitly allowed and correct.
4. Prefer explicit, inspectable artifacts over hidden behavior.
5. Every workflow must have a verification path.
6. The final system should feel like "LazyCodex reborn inside WorkBuddy," not "LazyCodex pasted into WorkBuddy."
7. Project-level `.workbuddy/` files for repo-local behavior; a plugin for reusable installable behavior.
8. Hooks only for deterministic enforcement, not vague guidance.
9. Subagents for specialized work with isolated context and scoped tool access.
10. MCP only where a real tool boundary is useful.
