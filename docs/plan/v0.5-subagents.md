Your task:
Implement workbuddy subagents that recreate LazyCodex role behavior using workbuddy’s agent model.

For each agent:
- Use YAML frontmatter.
- Include name.
- Include description with clear invocation conditions.
- Include model policy:
  - inherit unless there is a clear reason.
  - stronger model for planning/review/security.
  - faster model acceptable for indexing/status.
- Include effort/maxTurns if supported.
- Include tools or disallowedTools.
- Avoid broad write access for verifier/reviewer/security agents.
- Define mission.
- Define allowed actions.
- Define forbidden actions.
- Define required context files.
- Define output format.
- Define handoff format.
- Define verification responsibility.
- Define mapping to original LazyCodex behavior.
- Define how it should use workbuddy-native tools creatively.
Suggested authority boundaries:
- Orchestrator:
  Owns workflow state, task selection, delegation, merge decisions, and final completion claim.
- Planner:
  Owns read-only analysis and plan generation.
- Implementer:
  Owns bounded code/docs changes.
- Verifier:
  Owns command execution and verification summaries.
- Reviewer:
  Owns human-like review and accept/revise/reject decisions.
- Librarian:
  Owns memory, command index, parity ledger, and known-gap updates.
- Migration Planner:
  Owns host-adapter generation.
- Context Indexer:
  Owns repo map and LazyCodex method evidence indexing.
- Security Auditor:
  Owns permission, secret, unsafe command, and overreach review.
Create orchestration docs:
- docs/lazybuddy-agent-inventory.md
- docs/lazybuddy-agent-orchestration.md
- docs/lazybuddy-handoff-protocol.md
- docs/lazybuddy-parallelism-policy.md
Required orchestration flow:
init-deep
→ ulw-plan
→ orchestrator selects task
→ implementer performs bounded work
→ verifier runs checks
→ reviewer decides accept/revise/reject
→ librarian updates memory if accepted
→ ulw-loop continues if needed
→ finalizer produces parity report
Parallelization rules:
- Parallelize read-only analysis tasks.
- Parallelize isolated documentation tasks only when they touch different files.
- Do not allow two agents to mutate the same file in the same cycle.
- Verifier/reviewer/security auditor should be read-only by default.
- Coordinator/orchestrator owns final merge and completion claim.
Verification:
- Every agent has valid frontmatter.
- Every agent maps to at least one LazyCodex behavior or is marked workbuddy-native enhancement.
- No two agents have conflicting authority.
- Orchestrator flow can execute the full lifecycle.
- Run plugin validation if available.
- Update parity ledger.
Required output:
- Agent inventory
- Orchestration diagram in Markdown
- What I inspected
- What I found
- What I changed
- How to run it
- Verification performed
- Remaining gaps
- Next prompt to paste
