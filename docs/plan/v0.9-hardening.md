Your task:
Make the quality-control parts of LazyBuddy robust enough to evaluate real implementation work.
Implement or refine:
1. Verifier
   - discovers available test commands
   - classifies checks by relevance:
     - syntax
     - typecheck
     - lint
     - unit tests
     - integration tests
     - plugin validation
     - docs consistency
     - parity coverage
     - security checks
   - runs relevant checks
   - records failures
   - distinguishes:
     - hard failure
     - soft warning
     - skipped
     - not applicable
   - writes verification summary to .lazybuddy/runs/<run_id>/verification/
   - creates repair tasks for failures
2. Reviewer
   - reviews changed files against original intent
   - checks for overreach
   - checks for missing docs
   - checks for missing tests
   - checks for regressions
   - checks if LazyCodex semantics were preserved
   - checks if workbuddy-native adaptation is justified
   - produces accept/reject/revise decision
   - writes review summary to .lazybuddy/runs/<run_id>/review/
3. Librarian
   - updates memory after accepted changes
   - updates command index when workflows change
   - updates parity ledger
   - updates known gaps
   - updates risk register
   - updates operating manual when behavior changes
   - avoids rewriting canonical method map unless repo evidence changes
   - writes memory update record to .lazybuddy/runs/<run_id>/memory_updates/
