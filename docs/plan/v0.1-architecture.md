LazyBuddy v0.1 — full workbuddy-native architecture plan

LazyBuddy v0.1 — Design the LazyCodex-to-workbuddy architecture.
Use the v0.0 discovery files as source material:
- docs/lazycodex-canonical-method-map.md
- docs/lazybuddy-official-capability-map.md
- docs/lazybuddy-host-adaptation-map.md
- docs/lazybuddy-v0.0-discovery-report.md
Your task:
Create a full implementation plan for a workbuddy-native recreation of LazyCodex.
Design principles:
1. Preserve LazyCodex method semantics.
2. Use workbuddy-native features creatively.
3. Do not blindly copy files unless copying is explicitly allowed and is the correct migration mechanism.
4. Prefer explicit, inspectable artifacts over hidden behavior.
5. Every workflow must have a verification path.
6. The final system should feel like “LazyCodex reborn inside workbuddy,” not “LazyCodex pasted into workbuddy.”
7. Use project-level .workbuddy files for repo-local behavior.
8. Use a plugin for reusable installable behavior.
9. Use hooks only for deterministic enforcement, not vague guidance.
10. Use subagents for specialized work with isolated context and scoped tool access.
11. Use MCP only where a real tool boundary is useful.
12. Use Plan Mode for read-only planning.
13. Use headless mode, HTTP API, Agent SDK, or Channels only where they improve repeatable autonomous operation.
Architecture requirements:
Map LazyCodex concepts into workbuddy as follows, adjusting based on what the repo actually contains:
- Project memory:
  workbuddy.md, .workbuddy/workbuddy.md, .workbuddy/rules/*.md, optional AGENTS.md compatibility.
- Skills:
  Plugin skills/<name>/SKILL.md and, where project-local behavior is needed, .workbuddy/skills/<name>/SKILL.md.
- Commands:
  Plugin commands/*.md and .workbuddy/commands/*.md.
- Subagents:
  Plugin agents/*.md and .workbuddy/agents/*.md.
- Verification:
  scripts/lazybuddy-verify.*, test discovery, package scripts, manual smoke checks, parity checks.
- Hooks:
  Plugin hooks/hooks.json for lifecycle enforcement:
  SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, PreCompact, Stop, StopFailure, TaskCreated, TaskCompleted, SubagentStart, SubagentStop.
- MCP:
  Plugin .mcp.json and MCP servers for run ledger, source capture, parity dashboard, verification, and optional external tools.
- Long-running loop:
  Durable .lazybuddy/runs/<run_id>/ ledger plus loop protocol and checkpoint rules.
- Reviewer/verifier:
  Separate Skills and subagents with explicit accept/reject/revise decisions.
- Librarian:
  Memory/index/parity update workflow that only updates canonical method map when repo evidence changes.
- Migration planner:
  Repeatable workflow for porting LazyCodex semantics into another host.
- Optional automation:
  Headless mode, HTTP API, Agent SDK, and Channels for non-interactive or remote operation.
