# v1.2.0 migration guide — native host boundaries

v1.2.0 does not grant new host authority. CodeBuddy, WorkBuddy, and CodeBuddy
Code remain independent hosts, and package readiness never promotes host
readiness.

Before upgrading, run the current status route and inventory receipt-owned,
modified, linked, and caller-owned assets. Preserve everything not proven
receipt-owned. Select one host and one evidence mode; do not reuse evidence
from another build, session, host, or worktree.

Current writers emit the current readiness and host-adapter records. Treat v1
receipts as immutable historical compatibility inputs: do not rewrite them,
use them as active writers, or let them promote a current host. For rollback,
use plan-first offboard and remove only unmodified generated assets named by
their receipts. Preserve modified files, host settings, registrations, and
caller paths.
