**Your task: execute phase v0.10 — migration planner and host adapters.**

This phase generalizes the LazyCodex → WorkBuddy adaptation experience into a reusable migration planner that can port LazyCodex concepts to any agent host. It also creates templates and documents how Lazyworkbuddy itself was migrated.

### What to produce

**1. Harden the migration-planner skill** (`lazyworkbuddy-plugin/skills/migration-planner/SKILL.md`):
Add a complete 9-step migration workflow:
1. **Canonical repo inspection** — clone/read the source repo, identify all methods, skills, agents, hooks, MCP servers
2. **Method extraction** — extract exact method names and source file paths
3. **Host capability inventory** — inventory the target host's extension surfaces (skills, agents, hooks, MCP, commands, rules, etc.)
4. **Semantic mapping** — map each source method to a host-native implementation, distinguishing behavior (preserved) from implementation (adapted)
5. **Host-native adaptation** — design the adapted implementation using host-native surfaces
6. **Verification design** — define verification gates for each adapted method
7. **Implementation sequence** — create a versioned implementation plan (v0.0 → v0.N)
8. **Dogfood run** — run the adapted system on itself
9. **Final parity report** — compare adapted vs source, document gaps

The skill must require:
- Local source repo inspection (never guess from memory)
- Exact method names and source paths
- Host feature inventory (what the target host supports)
- Behavior-vs-implementation distinction
- Legal/license/IP boundary (clean-room adaptation, no copying protected material)
- Semantic mapping (not syntactic copying)
- Creative host-native adaptation
- Versioned implementation plan
- Verification gates
- Dogfood run
- Final parity report
