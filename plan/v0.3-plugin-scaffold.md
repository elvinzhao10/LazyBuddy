Your task:
Create the workbuddy plugin shell for Lazyworkbuddy.
Design:
The repo-local .workbuddy layer provides project memory and rules.
The plugin provides reusable installable behavior:
- skills
- commands
- agents
- hooks
- MCP servers
- scripts
- optional LSP/tool configs
Required structure:
lazyworkbuddy-plugin/
  .workbuddy-plugin/
    plugin.json
  README.md
  CHANGELOG.md
  commands/
  skills/
  agents/
  hooks/
    hooks.json
  mcp/
  scripts/
  schemas/
  tests/
  docs/
  .mcp.json
If the project prefers plugin-at-root instead of nested plugin directory, document the choice and ensure workbuddy plugin discovery works.
Create plugin manifest:
- .workbuddy-plugin/plugin.json
Manifest should include:
- name: lazyworkbuddy
- version: 0.1.0
- description
- author placeholder if unknown
- commands path if non-default
- skills path if non-default
- agents path if non-default
- hooks path if non-default
- mcpServers or .mcp.json reference if appropriate
Important:
- Components must live at the plugin root, not inside .workbuddy-plugin/.
- Use ${CODEBUDDY_PLUGIN_ROOT} for plugin-local scripts.
- Use ${CODEBUDDY_PLUGIN_DATA} for persistent plugin state, caches, installed dependencies, or generated durable plugin data.
- Do not put run-specific workspace state only in plugin data. Keep project run state in .lazyworkbuddy/ so it is inspectable and portable.
