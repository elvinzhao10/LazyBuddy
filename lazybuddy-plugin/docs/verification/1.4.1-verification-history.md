# Verification, history and scale — 1.4.1 development

This working-tree milestone combines the former 1.4.1 and 1.4.2 scopes. The published release remains 1.4.0 until a separate release is prepared and published.

## Workbench

Open Execution → run verification controls → Verification for a bound native run. Search task/criterion identities, filter verification state and traverse 25-row pages. Selecting a criterion exposes prior requirement and scenario definitions, attempt comparisons, failure promotion, local rerun reviews and scoped decision history. Older scenario records without retained definitions explicitly remain unreported.

The applicable-result column uses the projection's current attempt identity. Historical attempts remain selectable. Comparisons report differing criterion, plan or source revisions and missing consumption; matching reported revisions do not establish unrecorded dirty-file coverage or measured efficiency savings.

Promoting an observed failed attempt creates an unverified scenario with native attempt/source/criterion provenance. The verifier reference is a reference for the native workflow; the browser does not execute it. Existing independent completion authority still determines verification.

## Review and source binding

request_review, resolve_review and consume_review use the existing native command transaction, expected revision and stable command ID. A local review is bound to the criterion version, plan revision, captured plan digest, HEAD and a bounded source-content digest. Changed content at the same HEAD invalidates the subject. Once a criterion has a review, its native dispatcher rejects pending, rejected, stale or already-used approvals. It reserves an approved subject for the exact attempt before starting the process, through the existing native transaction. A worker reservation permits one distinct verifier continuation tied to that executor attempt. For reviewed verifier-only contexts, pass --role verifier and --executor-attempt-id when creating the context. Legacy consume_review records local attestation but cannot authorize a native attempt. Actor strings remain attribution, not authenticated host permission or proof of conversational adoption.

Source capture covers up to 5,000 tracked and non-ignored files, 32 MiB total, and executable bits in the canonical checkout. Native runtime stores are excluded; the run-owned plan has a separate digest. Symlinks, non-regular files, unstable captures and exceeded bounds make review unavailable. Ignored application files are outside this content capture. Native permissions and dispatch checks remain authoritative.

## Checkpoint history

The authenticated POST /api/history/query route accepts {"operation":"index","offset":0,"limit":25} and {"operation":"compare","before":CHECKPOINT_ID,"after":null}; null means the captured current state. IDs come from the index. It compares retained task definitions, dependencies, criteria/scenarios, execution state and decision records. It returns no raw command argv, environment, credential or verification authority.

The workbench disclosure loads checkpoint pages explicitly and renders changes in batches. Checkpoints represent retained command boundaries, not a complete recording of every host turn. Trae uses its native retained goal snapshots; older records may lack plan revision or decision history. Missing archives remain unavailable.

## Compaction and recovery

compact_history targets the bound run and requires the SHA-256 of the current runtime event source. It removes only duplicate events with identical identity/content. It rejects collisions and incomplete input, preserves failed attempts and retains the complete original ledger before publishing the new generation through the existing transaction journal. Retrying the same accepted command returns its original receipt.

Python-backed ports retain history/dashboard-REVISION/state.json, canonical-events.jsonl and compaction.json. Trae retains its native dashboard history and event archive. This reduces duplicate records in the active ledger; it does not claim reduced total archive storage. Never delete archives to bypass recovery errors.

## Acceptance boundary

Package/browser/HTTP checks are separate from live host loading, model execution, embedding, chat handoff and wake. Live-host acceptance is deferred by the maintainer as of 2026-10-30; unobserved host capabilities remain pending. The private coordination evidence records commands, failures, repairs, final package checks and replay measurements.
